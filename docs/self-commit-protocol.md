# Self‑Commit Protocol

This document describes the **model‑driven self‑commit workflow** used in this repository.  It is intended for human readers and for the automated harness that executes the model‑generated commands.

## Commit‑message hook

The repository’s local Git **commit‑msg hook** (installed in the developer’s `.git/hooks/` directory) enforces that every commit message contains the line:
```
TURN: builder
```
This check is performed by the local hook **outside of the public repository tree**; therefore the hook file is not visible in the source tree.  The hook ensures that the provenance of each change is recorded, but the hook itself is not part of the published codebase.

## Execution guards

All model‑generated actions are limited to the `docs/` directory.  The harness that runs the model also enforces two additional safeguards:
1. **Path restriction** – only files under `docs/` may be created or modified.
2. **Credential pattern refusal** – any content that matches common credential patterns (e.g., `AKIA...`, `ssh‑rsa ...`) is automatically rejected.
These guards are implemented in the execution environment (the harness) and are not represented by files in the repository.  They should be understood as runtime protections rather than repository‑intrinsic properties.

## Human oversight

After the model creates a commit, the harness automatically runs `git push`.  The push is not blocked by a pre‑push hook; instead, oversight occurs **after the push** through the independent review loop (see `docs/review-loop.md`).  Human reviewers inspect the diff that has been pushed and may request changes, which the model then addresses in a subsequent cycle.

## Provenance statement

Each commit generated by the model includes the required `TURN: builder` line **and** an explicit provenance note in the commit message, for example:
```
[PROVENANCE] This change was authored by the model (Groq gpt‑oss‑120b) and executed by the repository harness.
TURN: builder
```
The line `TURN: builder` satisfies the hook, while the provenance note separates model‑authored content from operator record‑keeping.
